Заказы Kwork с 40+ откликами нужно глушить (MidCompetitionBorderlineSkip / HighCompetitionSkip), даже если Haiku поставил высокий скор (8/10 fullstack в ядре компетенций).

**Why:** У пользователя профиль novice (1 отзыв, без медали уровня). Из 50 откликов без отзывов не выделиться — заказчик нас не заметит, коннект (квота 30/мес) уходит в никуда. Скорость отклика не работает на массовых заказах.

**How to apply:** НЕ предлагать ослабить порог глушения для BIG/высокоскорных заказов с большой конкуренцией. Я однажды предложил «BIG score≥8 пропускать при 40+ откликов» — пользователь отверг. Агрессивное глушение по конкуренции (волна 3, идея 48) — это by design, оставлять как есть. Целимся в узкие ниши с низкой конкуренцией, не в массовку. Связано с [[project_freel_bot]].

**Обновление 10.07.2026 (аудит + исправление):** гейт при находке = HIGH_OFFERS_ABS (30), было 50. Я сначала поставил 8 «по данным недели» — пользователь отверг: это ломало договорённость Group 4 про два порога (30 по абсолюту = мясорубка; <15 при кучном темпе = fresh/перепроверить, НЕ резать). Узкий годный заказ нормально набирает 8-14 откликов за часы — выжившие той же недели («Фиды» 1→9 slow, «Ямаркет» 4→13 slow) при поздней находке попали бы под гейт 8. Урок: НЕ предлагать пороги ниже 15-20 по абсолюту без данных о темпе; недельная выборка «все n0≥8 флипнулись» — survivorship bias. Полоса 8-29 — velocity-гейт (FAST≥20/BIG≥25) + перепроверки. Обратная сторона: скор ≥6 при <5 откликах = полноценная карточка (NarrowNicheGo) — узкая ниша перевешивает порог скора. Низкая конкуренция — критерий №1 в обе стороны.
